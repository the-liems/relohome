# Internal APIs — Intake and Routing Orchestrator

Canonical contracts live in Python/Pydantic. Each running app exposes generated
`/openapi.json` and Swagger `/docs`; this document defines semantics, not a second schema.

Two services: Intake `8011`, Routing Orchestrator `8012`. All `/v1` endpoints require
their service bearer token. Tokens remain in backend infrastructure, not browsers.
Workflow endpoints also take `X-Owner-ID`, set only by the authenticated trusted
caller. The services do not implement end-user login. A caller holding the service
token is trusted to supply that identity correctly.

| Service / method | Path | Behavior |
|---|---|---|
| Both GET | `/health` | Process liveness, no provider probe |
| Both GET | `/ready` | Configuration/local storage readiness; see capability flags |
| Intake POST | `/v1/intake` | Real LLM extraction + deterministic validation |
| Routing GET | `/v1/capabilities` | Actual registered schemas; execution disconnected |
| Routing POST | `/v1/plans/validate` | Validate a plan without LLM/provider calls or persistence |
| Routing POST | `/v1/workflows` | Plan from supplied IntakeResult; persist idempotently |
| Routing GET | `/v1/workflows/{id}` | Load owner-scoped state and refresh expired leases/approvals |
| Routing GET | `/v1/workflows/{id}/events` | Latest 200 metadata-only lifecycle events |
| Routing POST | `/v1/workflows/{id}/advance` | One scheduling wave inside Routing; disconnected in standalone |
| Routing POST | `/v1/workflows/{id}/replan` | New supplied IntakeResult; dependency-aware invalidation |
| Routing POST | `/v1/workflows/{id}/cancel` | Stop local workflow; does not cancel provider order |
| Routing POST | `/v1/workflows/{id}/tasks/{task}/reject` | Reject pending task and descendants |
| Routing POST | `/v1/workflows/{id}/tasks/{task}/approve` | Trusted approval token only; bind user confirmation |

`POST /v1/workflows` binds `(owner_id, session_id, request_id)` to a request hash;
replaying identical input returns the existing workflow. Changing input under the
same request ID returns 409. Later mutations require `expected_revision` from the
latest response. Conflict is 409 `REVISION_CONFLICT`: reload before deciding whether
to retry. `plan_version` changes only on replan; `revision` changes on persisted updates.

`PlanTask.arguments_json` is a JSON-encoded object so the LLM's structured schema
can remain strict while different domain tools have different input fields.
`input_refs` binds a top-level argument to a validated dependency result via RFC
6901 JSON pointer. Literal and reference cannot both assign the same argument.
All references require explicit `depends_on`; unknown tool and cyclic plan fail.
Backend-owned `approval_id`, `workflow_id`, `action_id` are inserted by control code,
never generated by the planning model. They cannot be overridden by input_refs.

Approval body contains expected revision, UUID approval ID, actor, payload hash
returned by the workflow, and aware expiry. Its lifetime is <=30 minutes. Changing
plan/input/dependency/expiry revokes its usability. For Moving, the approval ID
must ultimately name a matching real record in Moving's backend; that bridge is
not connected in this release. General callers cannot create those records here.

Errors use `error.code`, a safe `message`, `retryable`, `request_id`; validation
errors identify field paths without echoing submitted values. Headers include
`X-Request-ID` and `Cache-Control: no-store`. Endpoint OpenAPI remains readable for
local development; deployment must keep these services on internal networks.

Intake `/ready` returns 503 without key/token. Routing `/ready` can return ready
for its deterministic contract/state APIs with `planning: llm_not_configured`;
it reports `execution: disconnected` explicitly. A configured key is not a live
provider connectivity test. LLM-backed requests still fail clearly when unavailable.
